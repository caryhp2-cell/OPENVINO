OpenVINO ResNet-50 壓力測試教學

Windows 11 + PowerShell 版。流程採用固定 Python 虛擬環境、固定 OpenVINO 版本、官方 OpenVINO IR ResNet-50 模型，目標是把環境變數與套件版本問題降到最低。

0. 正式操作前：先確認可信套件與版本

請先做這段，不要直接跳到壓測。OpenVINO、Python、NPU/GPU 驅動版本不一致時，常見症狀是找不到 benchmark_app、找不到 NPU/GPU 裝置、或模型編譯失敗。
項目 建議版本 / 來源 為什麼
Windows Windows 11 64-bit，建議更新到最新正式版 避免舊版驅動模型與 NPU/GPU runtime 不相容。
Python 本教學固定使用 Python 3.12 x64，從 Python.org 或 winget 安裝，不建議 Microsoft Store 版 Python 3.12 不是最新版本；這裡選它是為了穩定與可重現。Store 版 Python 常造成 PATH、權限與虛擬環境問題。
OpenVINO openvino==2026.1.0 固定版本可重現；官方文件目前列出 OpenVINO 2026.1。
模型 OpenVINO/resnet50-int8-ov OpenVINO 官方 Hugging Face 模型，已是 IR 格式，避免 TensorFlow/PyTorch 轉換地雷。
驅動 Intel Graphics Driver / Intel NPU Driver 使用 Intel 官方或 OEM 最新正式版 OpenVINO 能否看到 GPU 或 NPU 主要取決於驅動。

1. 建立乾淨工作資料夾

以下指令都在 PowerShell 執行。建議使用全新資料夾，避免污染你原本的 Python 環境。

$ErrorActionPreference = "Stop"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

$WorkDir = "$env:USERPROFILE\Documents\openvino-resnet50-stress"
New-Item -ItemType Directory -Force -Path $WorkDir | Out-Null
Set-Location $WorkDir

Write-Host "Working directory: $PWD"

2. 安裝與確認 Python 3.12 x64

Python 3.12 不是最新版本。本教學建議固定使用 Python 3.12 x64，是為了讓 OpenVINO、pip wheel、venv 與 Windows PowerShell 流程更穩定、可重現。如果你想使用更新的 Python，請先確認 OpenVINO 與相關套件已支援該版本。

如果你已經有 Python 3.12 x64，可以先跑確認指令。沒有的話，先用 winget 安裝。

2.1 安裝本教學指定版本：Python 3.12 x64

winget install --id Python.Python.3.12 --source winget --accept-package-agreements --accept-source-agreements

2.2 關掉 PowerShell 後重新開啟，再確認版本

py -0p
py -3.12 -c "import platform, sys; print(sys.version); print(platform.architecture())"
你要看到 Python 3.12，且架構是 64-bit。若 py -3.12 找不到，重新開 PowerShell；仍找不到再重開機。

3. 建立並啟用虛擬環境

這段會把所有 Python 套件鎖在 .venv，不要用系統全域 pip。

$ErrorActionPreference = "Stop"
Set-Location "$env:USERPROFILE\Documents\openvino-resnet50-stress"

py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip setuptools wheel
python -m pip --version
python --version
若 PowerShell 擋住啟用腳本，請在同一個視窗先跑：Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force。不要改全系統 ExecutionPolicy。

4. 安裝 OpenVINO 與下載工具

這裡固定 OpenVINO 版本。模型下載改用 PowerShell 直接抓 .xml 與 .bin，減少額外 Python CLI 依賴。

python -m pip install "openvino==2026.1.0"

python -c "import openvino as ov; print('OpenVINO:', ov.__version__)"
benchmark_app -h | Select-Object -First 20
官方文件說明，透過 PyPI 安裝 OpenVINO 後會自動提供 Python 版 benchmark_app。如果這裡找不到，通常代表虛擬環境沒有啟用。

5. 下載 ResNet-50 OpenVINO IR 模型

使用 OpenVINO 官方 Hugging Face 模型 OpenVINO/resnet50-int8-ov。它包含 resnet50.xml 與 resnet50.bin。

$ModelDir = "$PWD\models\resnet50-int8-ov"
New-Item -ItemType Directory -Force -Path $ModelDir | Out-Null

$XmlUrl = "https://huggingface.co/OpenVINO/resnet50-int8-ov/resolve/main/resnet50.xml?download=true"
$BinUrl = "https://huggingface.co/OpenVINO/resnet50-int8-ov/resolve/main/resnet50.bin?download=true"

Invoke-WebRequest -Uri $XmlUrl -OutFile "$ModelDir\resnet50.xml"
Invoke-WebRequest -Uri $BinUrl -OutFile "$ModelDir\resnet50.bin"

Get-ChildItem $ModelDir
$ModelXml = Join-Path $ModelDir "resnet50.xml"
Test-Path $ModelXml

如果公司網路擋 Hugging Face，改用瀏覽器打開模型頁下載 resnet50.xml 和 resnet50.bin，放進同一個 $ModelDir。

6. 確認 OpenVINO 可用裝置

壓測前先列出 OpenVINO 看得到的裝置。常見結果是 CPU、GPU、NPU，依你的硬體與驅動而定。

@'
import openvino as ov

core = ov.Core()
print("OpenVINO:", ov.__version__)
print("Available devices:", core.available_devices)
for device in core.available_devices:
    try:
        name = core.get_property(device, "FULL_DEVICE_NAME")
    except Exception as exc:
        name = f"Cannot query name: {exc}"
    print(f"{device}: {name}")
'@ | python -
如果沒有看到 NPU，先不要怪 Python。請先更新 Intel NPU Driver / Intel Graphics Driver，並重開機後再跑一次。沒有 NPU 硬體的機器當然也不會列出 NPU。

7. 先跑 60 秒基準測試

先用 CPU 跑通，確認模型與 OpenVINO 安裝沒問題。壓測前一定要做這個 smoke test。

$ModelXml = "$PWD\models\resnet50-int8-ov\resnet50.xml"
benchmark_app -m $ModelXml -d CPU -t 60 -api async -hint throughput

如果有 GPU：

benchmark_app -m $ModelXml -d GPU -t 60 -api async -hint throughput

如果有 NPU：

benchmark_app -m $ModelXml -d NPU -t 60 -api async -hint throughput
benchmark_app 預設會用隨機輸入資料測效能，輸出會包含 latency 與 throughput。ResNet-50 是 image classification 模型，這裡重點是硬體推論壓力，不是驗證分類準確率。

8. 壓力測試：單裝置長時間跑

這是最穩的壓測方式。先從 CPU 或 GPU 開始，NPU 則視硬體與驅動支援狀況執行。

$Device = "CPU"     # 可改成 "GPU" 或 "NPU"
$Seconds = 600     # 10 分鐘；想跑 1 小時改 3600
$LogDir = "$PWD\logs"
$ModelXml = "$PWD\models\resnet50-int8-ov\resnet50.xml"

New-Item -ItemType Directory -Force -Path $LogDir | Out-Null

benchmark_app -m $ModelXml -d $Device -t $Seconds -api async -hint throughput *>&1 |
  Tee-Object -FilePath "$LogDir\benchmark_${Device}_${Seconds}s.log"

壓測期間建議同時開工作管理員，觀察 CPU、GPU、NPU、記憶體與溫度。如果你有 HWiNFO、Intel Arc Control 或 OEM 工具，也可以同步記錄功耗與溫度。

9. 壓力測試：多工作並行

這段會開多個 PowerShell background jobs 同時跑 benchmark_app。CPU/GPU 可以逐步加 worker；NPU 建議先從 1 個 worker 開始。

$Device = "CPU"     # 可改成 "GPU"；NPU 建議先用 1 worker
$Workers = 4
$Seconds = 300
$Root = "$PWD"
$ModelXml = "$PWD\models\resnet50-int8-ov\resnet50.xml"
$LogDir = "$PWD\logs"

New-Item -ItemType Directory -Force -Path $LogDir | Out-Null
Get-Job | Remove-Job -Force

1..$Workers | ForEach-Object {
  $Index = $_
  Start-Job -Name "ov-$Device-$Index" -ScriptBlock {
    param($Root, $ModelXml, $Device, $Seconds, $Index)
    Set-Location $Root
    .\.venv\Scripts\Activate.ps1
    benchmark_app -m $ModelXml -d $Device -t $Seconds -api async -hint throughput *>&1 |
      Tee-Object -FilePath ".\logs\benchmark_${Device}_worker${Index}_${Seconds}s.log"
  } -ArgumentList $Root, $ModelXml, $Device, $Seconds, $Index
}

Get-Job
Get-Job | Wait-Job
Get-Job | Receive-Job
Get-Job | Remove-Job
如果多 worker 讓系統卡住，請降低 $Workers。若 NPU 編譯或執行失敗，先用 $Workers = 1，再試 AUTO:NPU,CPU。

10. 失敗時的穩定排除順序

  1. 確認目前 PowerShell 有啟用 .venv：提示字元前面應有 (.venv)。
  2. 確認 python -c "import openvino as ov; print(ov.__version__)" 顯示 2026.1.0。
  3. 確認 benchmark_app -h 能顯示說明。
  4. 確認 Test-Path .\models\resnet50-int8-ov\resnet50.xml 是 True。
  5. 確認 core.available_devices 有你要測的裝置。
  6. 如果 NPU 不存在，更新 Intel NPU Driver 與 Intel Graphics Driver，重開機後再測。
  7. 如果只有 GPU/NPU 失敗，先用 CPU 跑通，確認不是模型或 Python 問題。
# 一次跑完最常用的自我檢查
.\.venv\Scripts\Activate.ps1
python --version
python -m pip --version
python -c "import openvino as ov; print(ov.__version__)"
benchmark_app -h | Select-Object -First 5
Test-Path ".\models\resnet50-int8-ov\resnet50.xml"
@'
import openvino as ov
core = ov.Core()
print(core.available_devices)
'@ | python -

11. 建議測試矩陣

階段 裝置 時間 Worker 目的
Smoke test CPU 60 秒 1 確認 OpenVINO、模型、benchmark_app 正常。
單裝置基準 CPU / GPU / NPU 300 秒 1 取得各裝置 baseline throughput 與 latency。
長時間穩定性 目標裝置 3600 秒 1 觀察溫度、降頻、driver reset、記憶體成長。
多工作壓力 CPU / GPU 300-1800 秒 2、4、8 逐步增加 測系統吞吐、排程與穩定性。
NPU 保守壓測 NPU 300-1800 秒 1 起跳 NPU 對模型與驅動較敏感，先確認單工作穩定。

12. 將壓測結果換算成 TOPS，並與 Intel 官網規格比較

Intel 官網常見的 NPU 峰值 TOPS (Int8) 是硬體在理想條件下的理論峰值。benchmark_app 測到的是模型在 OpenVINO runtime、driver、模型圖、memory access、排程與裝置支援限制下的實際吞吐量。兩者用途不同，請用「有效 TOPS / 峰值 TOPS」看利用率，不要期待實測等於官網峰值。

12.1 最簡單的算法

先從 benchmark_app log 找到 throughput，也就是每秒推論次數 FPS：

Throughput: 123.45 FPS

然後只要套兩個公式：

Effective TOPS = FPS × Model GOPS per inference ÷ 1000
Peak utilization (%) = Effective TOPS ÷ Peak TOPS from vendor website × 100

Peak TOPS 是 Intel 官網或 OEM 規格頁上的 NPU 峰值。Effective TOPS 是這次壓測跑出來的模型有效吞吐。兩個數字相除，才是這個 workload 對理論峰值的利用率。

12.2 ResNet-50 建議直接用 8.2 GOPS

ResNet-50 常見估算約為 4.1 GMAC。為了跟硬體 TOPS 規格比較，通常把 1 個 MAC 視為 multiply + accumulate 兩個 operation，所以教學中直接使用：

ResNet-50 Model GOPS per inference = 8.2
模型 建議 GOPS per inference 用途
ResNet-50 8.2 GOPS 適合把 benchmark_app 的 FPS 快速換算成 Effective TOPS。

如果你換成其他模型，請把 $ModelGopsPerInference 改成該模型對應的 GOPS。沒有可靠數字時，不要硬算 TOPS；先只比較 FPS、latency、功耗與穩定性。

12.3 PowerShell 自動換算

請把 $PeakTopsFromSpec 改成測試機器在 Intel 官網或 OEM 規格頁看到的 NPU 峰值 TOPS。不同 CPU / NPU 世代數字會不同，所以不要固定使用範例值。

$LogFile = ".\logs\benchmark_NPU_600s.log"
$PeakTopsFromSpec = 13.0       # 範例值：請改成你的機器規格
$ModelGopsPerInference = 8.2   # ResNet-50 TOPS 比較口徑

$Text = Get-Content $LogFile -Raw
$Match = [regex]::Match($Text, "Throughput:\s+([0-9.]+)\s+FPS")
if (-not $Match.Success) {
  throw "找不到 Throughput: xxx FPS。請確認 log 檔是 benchmark_app 的輸出。"
}

$Fps = [double]$Match.Groups[1].Value
$EffectiveTops = $Fps * $ModelGopsPerInference / 1000.0
$PeakUtilization = $EffectiveTops / $PeakTopsFromSpec * 100.0

[pscustomobject]@{
  LogFile = $LogFile
  FPS = [math]::Round($Fps, 2)
  Model_GOPS_Per_Inference = $ModelGopsPerInference
  Effective_TOPS = [math]::Round($EffectiveTops, 3)
  Peak_TOPS_From_Spec = $PeakTopsFromSpec
  Peak_Utilization_Percent = [math]::Round($PeakUtilization, 2)
} | Format-List

12.4 手算範例

假設 ResNet-50 壓測 log 顯示 Throughput: 500 FPS，而這台機器官網 NPU 峰值是 13 TOPS：

Effective TOPS = 500 × 8.2 ÷ 1000 = 4.10 TOPS
Peak utilization = 4.10 ÷ 13 × 100 = 31.54%

如果另一台機器官網 NPU 峰值是 40 TOPS，同樣 500 FPS 的利用率會變成：

Peak utilization = 4.10 ÷ 40 × 100 = 10.25%

12.5 解讀結果時要注意

  • Peak TOPS 是 NPU 的理論 INT8 峰值，不是任何模型都會達到的 benchmark 分數。
  • ResNet-50 是否完整跑在 NPU、是否有 fallback、是否受 memory bandwidth 限制，都會影響有效 TOPS。
  • 如果 benchmark_app log 顯示裝置不是 NPU，或你使用 AUTO:NPU,CPU，結果就不能直接視為純 NPU TOPS。
  • 不同 batch、stream、driver、電源模式、散熱狀態都會改變 FPS；比較前請固定測試條件。
  • 若要更接近官網峰值，需要使用能高度貼合 NPU INT8 execution path 的模型與 workload；ResNet-50 是實務壓測參考，不是硬體峰值測試。

13. 適合 NPU INT8 壓測的模型與 workload

想讓結果更貼近 NPU 的 INT8 execution path，請優先挑選已量化、靜態 shape、運算主體規則的模型。OpenVINO NPU 文件也提醒，NPU 支援量化模型可為 INT8 或 FP16-INT8，且目前 NPU 對 static shape 最友善。

13.1 優先選擇

類型 候選模型 原因
Image Classification CNN resnet-50, mobilenet-v2, mobilenet-v3, efficientnet-b0, googlenet-v4 Conv-heavy、static input 容易固定，適合吞吐壓測與 TOPS 換算。
小型 Object Detection / OCR backbone ssdlite_mobilenet_v2, pp-ocr-det, pp-ocr-rec 實務用途明確，但要注意 NMS、decode、後處理可能拉低有效 TOPS。
Audio / Speech 小模型 aclnet-int8, DNS / keyword spotting 類模型 模型較小、輸入規則，適合檢查 NPU 穩定性與低功耗推論。
NLP encoder BERT 類 INT8 或 FP16-INT8 encoder MatMul-heavy，可測另一種 workload；但 TOPS 換算通常沒有 ResNet-50 直覺。

13.2 選模型的檢查清單

  • 優先選 INT8 或 FP16-INT8 模型。
  • 優先選固定輸入大小，例如 1x3x224x224。
  • 優先選 OpenVINO IR 格式，也就是同時有 .xml 與 .bin。
  • 用 -d NPU 單獨測，避免 AUTO:NPU,CPU 混入 fallback。
  • 盡量把 resize、decode、NMS、tokenizer、postprocess 排除在 TOPS 換算之外。

13.3 不建議直接拿來比 Peak TOPS

  • LLM token generation：瓶頸常在 memory、KV cache、token loop，不是單純 INT8 dense compute。
  • 完整 YOLO pipeline：NMS、decode、resize 與 postprocess 會讓有效 TOPS 變低。
  • dynamic shape 模型：NPU 路徑更容易受限制或編譯失敗。
  • FP16-only 模型：可以測 NPU，但不適合直接對比官網 Int8 TOPS。
