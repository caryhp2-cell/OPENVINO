OpenVINO ResNet-50 Stress Test Guide

Windows 11 + PowerShell workflow. This guide uses a fixed Python virtual environment, a pinned OpenVINO version, and the official OpenVINO IR ResNet-50 model to reduce environment-variable and package-version problems.

0. Before You Start: Confirm Trusted Packages and Versions

Run this preparation first. Do not jump directly to the stress test. When OpenVINO, Python, NPU/GPU drivers, or runtime versions do not match, common symptoms include missing benchmark_app, missing NPU/GPU devices, or model compilation failures.
Item Recommended Version / Source Reason
Windows Windows 11 64-bit, preferably updated to the latest stable release Avoid old driver/runtime combinations that may not work with NPU or GPU plugins.
Python Python 3.12 x64 from Python.org or winget. The Microsoft Store build is not recommended. Python 3.12 is chosen for stability and reproducibility. Store Python often causes PATH, permission, and virtual environment confusion.
OpenVINO openvino==2026.1.0 Pinning the version makes the workflow reproducible.
Model OpenVINO/resnet50-int8-ov This official Hugging Face model is already in OpenVINO IR format, so you avoid TensorFlow/PyTorch conversion issues.
Drivers Latest stable Intel Graphics Driver and Intel NPU Driver from Intel or your OEM Whether OpenVINO can see GPU or NPU mainly depends on driver support.

1. Create a Clean Working Folder

Run the commands below in PowerShell. You can change only the $WorkDir value if you want to use a different folder. Later steps reuse the saved working-folder value, so they will not depend on a hard-coded path.

$ErrorActionPreference = "Stop"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

$WorkDir = Join-Path $env:USERPROFILE "Documents\openvino-resnet50-stress"
New-Item -ItemType Directory -Force -Path $WorkDir | Out-Null
Set-Location -LiteralPath $WorkDir

$WorkDir = (Get-Location).ProviderPath
$env:OPENVINO_RESNET50_STRESS_WORKDIR = $WorkDir
[Environment]::SetEnvironmentVariable("OPENVINO_RESNET50_STRESS_WORKDIR", $WorkDir, "User")

Write-Host "Working directory: $WorkDir"
Write-Host "Saved as OPENVINO_RESNET50_STRESS_WORKDIR for later steps."
If you already cloned this repository and want to use that folder, open PowerShell in the repository folder first, then replace the $WorkDir = ... line with $WorkDir = (Get-Location).ProviderPath.

2. Install and Confirm Python 3.12 x64

Python 3.12 is not the newest Python release. This guide pins Python 3.12 x64 because it keeps OpenVINO, pip wheels, venv, and Windows PowerShell behavior more stable and reproducible. If you want to use a newer Python version, confirm OpenVINO and related packages support it first.

If Python 3.12 x64 is already installed, run the version check first. Otherwise, install it with winget.

2.1 Install Python 3.12 x64

winget install --id Python.Python.3.12 --source winget --accept-package-agreements --accept-source-agreements

2.2 Close PowerShell, Open It Again, Then Confirm the Version

py -0p
py -3.12 -c "import platform, sys; print(sys.version); print(platform.architecture())"
You should see Python 3.12 and a 64-bit architecture. If py -3.12 is not found, restart PowerShell. If it is still missing, restart Windows and try again.

3. Create and Activate the Virtual Environment

This step installs all Python packages inside .venv. It reuses the working folder saved in Step 1, so it will still work if you changed the path there.

$ErrorActionPreference = "Stop"
$WorkDir = $env:OPENVINO_RESNET50_STRESS_WORKDIR

if ([string]::IsNullOrWhiteSpace($WorkDir) -or -not (Test-Path -LiteralPath $WorkDir)) {
  throw "Cannot find OPENVINO_RESNET50_STRESS_WORKDIR. Run Step 1 first, or set this environment variable to your working folder."
}

Set-Location -LiteralPath $WorkDir
Write-Host "Working directory: $PWD"

py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip setuptools wheel
python -m pip --version
python --version
If PowerShell blocks the activation script, run this in the same window first: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force. Do not change the machine-wide execution policy.

4. Install OpenVINO and Confirm the Benchmark Tool

This guide pins the OpenVINO version. Model download is done directly with PowerShell to fetch the .xml and .bin files, which avoids extra Python CLI dependencies.

python -m pip install "openvino==2026.1.0"

python -c "import openvino as ov; print('OpenVINO:', ov.__version__)"
benchmark_app -h | Select-Object -First 20
The PyPI OpenVINO package provides the Python version of benchmark_app. If this command is not found, the virtual environment is usually not activated.

5. Download the ResNet-50 OpenVINO IR Model

Use the official OpenVINO Hugging Face model OpenVINO/resnet50-int8-ov. It contains resnet50.xml and resnet50.bin.

$ModelDir = "$PWD\models\resnet50-int8-ov"
New-Item -ItemType Directory -Force -Path $ModelDir | Out-Null

$XmlUrl = "https://huggingface.co/OpenVINO/resnet50-int8-ov/resolve/main/resnet50.xml?download=true"
$BinUrl = "https://huggingface.co/OpenVINO/resnet50-int8-ov/resolve/main/resnet50.bin?download=true"

Invoke-WebRequest -Uri $XmlUrl -OutFile "$ModelDir\resnet50.xml"
Invoke-WebRequest -Uri $BinUrl -OutFile "$ModelDir\resnet50.bin"

Get-ChildItem $ModelDir
$ModelXml = Join-Path $ModelDir "resnet50.xml"
Test-Path $ModelXml

If a company network blocks Hugging Face, open the model page in a browser, download resnet50.xml and resnet50.bin, and place both files in the same $ModelDir.

6. Confirm OpenVINO Devices

Before stress testing, list the devices OpenVINO can see. Common results include CPU, GPU, and NPU, depending on your hardware and drivers.

@'
import openvino as ov

core = ov.Core()
print("OpenVINO:", ov.__version__)
print("Available devices:", core.available_devices)
for device in core.available_devices:
    try:
        name = core.get_property(device, "FULL_DEVICE_NAME")
    except Exception as exc:
        name = f"Cannot query name: {exc}"
    print(f"{device}: {name}")
'@ | python -
If NPU is not listed, do not blame Python first. Update the Intel NPU Driver and Intel Graphics Driver, restart Windows, and run the check again. Machines without NPU hardware will not list NPU.

7. Run a 60-Second Baseline Test First

Start with CPU to confirm the model and OpenVINO installation work. Always run this smoke test before a longer stress test.

$ModelXml = "$PWD\models\resnet50-int8-ov\resnet50.xml"
benchmark_app -m $ModelXml -d CPU -t 60 -api async -hint throughput

If GPU is available:

benchmark_app -m $ModelXml -d GPU -t 60 -api async -hint throughput

If NPU is available:

benchmark_app -m $ModelXml -d NPU -t 60 -api async -hint throughput
benchmark_app uses generated input data by default and reports latency and throughput. ResNet-50 is an image classification model, but the goal here is inference stress testing, not classification accuracy.

8. Stress Test: Long Single-Device Run

This is the most stable stress-test mode. Start with CPU or GPU. Run NPU only when the hardware and driver support are confirmed.

$Device = "CPU"     # Change to "GPU" or "NPU" when available
$Seconds = 600     # 10 minutes; use 3600 for 1 hour
$LogDir = "$PWD\logs"
$ModelXml = "$PWD\models\resnet50-int8-ov\resnet50.xml"

New-Item -ItemType Directory -Force -Path $LogDir | Out-Null

benchmark_app -m $ModelXml -d $Device -t $Seconds -api async -hint throughput *>&1 |
  Tee-Object -FilePath "$LogDir\benchmark_${Device}_${Seconds}s.log"

During the stress test, keep Task Manager open and watch CPU, GPU, NPU, memory, and temperature. If you have HWiNFO, Intel Arc Control, or an OEM monitoring tool, record power and temperature as well.

9. Stress Test: Multiple Parallel Workers

This step starts multiple PowerShell background jobs that run benchmark_app in parallel. Increase CPU/GPU workers gradually. For NPU, start with one worker.

$Device = "CPU"     # Change to "GPU"; for NPU, start with 1 worker
$Workers = 4
$Seconds = 300
$Root = "$PWD"
$ModelXml = "$PWD\models\resnet50-int8-ov\resnet50.xml"
$LogDir = "$PWD\logs"

New-Item -ItemType Directory -Force -Path $LogDir | Out-Null
Get-Job | Remove-Job -Force

1..$Workers | ForEach-Object {
  $Index = $_
  Start-Job -Name "ov-$Device-$Index" -ScriptBlock {
    param($Root, $ModelXml, $Device, $Seconds, $Index)
    Set-Location -LiteralPath $Root
    .\.venv\Scripts\Activate.ps1
    benchmark_app -m $ModelXml -d $Device -t $Seconds -api async -hint throughput *>&1 |
      Tee-Object -FilePath ".\logs\benchmark_${Device}_worker${Index}_${Seconds}s.log"
  } -ArgumentList $Root, $ModelXml, $Device, $Seconds, $Index
}

Get-Job
Get-Job | Wait-Job
Get-Job | Receive-Job
Get-Job | Remove-Job
If multiple workers make the system unresponsive, lower $Workers. If NPU compilation or execution fails, try $Workers = 1 first, then test AUTO:NPU,CPU separately if needed.

10. Stable Troubleshooting Order

  1. Confirm the current PowerShell prompt starts with (.venv).
  2. Confirm python -c "import openvino as ov; print(ov.__version__)" prints 2026.1.0.
  3. Confirm benchmark_app -h prints help text.
  4. Confirm Test-Path .\models\resnet50-int8-ov\resnet50.xml returns True.
  5. Confirm core.available_devices includes the device you want to test.
  6. If NPU is missing, update the Intel NPU Driver and Intel Graphics Driver, restart Windows, and test again.
  7. If only GPU or NPU fails, run CPU first to confirm the model and Python environment are not the problem.

12. Convert Stress-Test Results to TOPS and Compare with Intel Specifications

The NPU peak TOPS (INT8) number on Intel or OEM specification pages is a theoretical hardware peak under ideal conditions. benchmark_app measures real model throughput under OpenVINO runtime, driver, graph, memory, scheduling, and device-support limits. Use Effective TOPS / Peak TOPS as a workload utilization estimate. Do not expect measured throughput to equal the vendor peak.

12.1 Simple Formula

First, find the throughput value in the benchmark_app log. It is the number of inferences per second, reported as FPS:

Throughput: 123.45 FPS

Then use these two formulas:

Effective TOPS = FPS * Model GOPS per inference / 1000
Peak utilization (%) = Effective TOPS / Peak TOPS from vendor website * 100

Peak TOPS comes from the Intel or OEM specification page. Effective TOPS is the measured model throughput from this stress test. The ratio tells you how much of the theoretical peak this workload uses.

12.2 For ResNet-50, Use 8.2 GOPS Directly

ResNet-50 is commonly estimated at about 4.1 GMAC. For comparison with hardware TOPS specifications, one MAC is usually counted as two operations: multiply plus accumulate. For this guide, use:

ResNet-50 Model GOPS per inference = 8.2
Model Recommended GOPS per Inference Use
ResNet-50 8.2 GOPS Use this to quickly convert benchmark_app FPS into Effective TOPS.

If you switch to a different model, replace the model GOPS value with a reliable number for that model. If you do not have a reliable number, do not force a TOPS calculation. Compare FPS, latency, power, and stability instead.

Manual Example

Assume the ResNet-50 stress-test log reports Throughput: 500 FPS, and the machine's official NPU peak is 13 TOPS:

Effective TOPS = 500 * 8.2 / 1000 = 4.10 TOPS
Peak utilization = 4.10 / 13 * 100 = 31.54%

If another machine has an official NPU peak of 40 TOPS, the same 500 FPS result becomes:

Peak utilization = 4.10 / 40 * 100 = 10.25%

Notes for Interpreting Results

  • Peak TOPS is the theoretical INT8 NPU peak. It is not a benchmark score every model should reach.
  • Whether ResNet-50 fully runs on NPU, uses fallback, or is limited by memory bandwidth will affect Effective TOPS.
  • If the benchmark_app log shows a device other than NPU, or if you used AUTO:NPU,CPU, do not treat the result as pure NPU TOPS.
  • Batch size, streams, driver version, power mode, and thermal state can all change FPS. Fix test conditions before comparing machines.
  • To get closer to vendor peak numbers, use a workload that closely matches the NPU INT8 execution path. ResNet-50 is a practical stress-test reference, not a hardware-peak microbenchmark.

13. Models and Workloads Suitable for NPU INT8 Stress Testing

To make results closer to the NPU INT8 execution path, prefer quantized models with static shapes and regular compute patterns. OpenVINO NPU documentation also notes that NPU-supported quantized models can be INT8 or FP16-INT8, and that static shapes are currently the most NPU-friendly.

13.1 Preferred Choices

Type Candidate Models Reason
Image classification CNN resnet-50, mobilenet-v2, mobilenet-v3, efficientnet-b0, googlenet-v4 Conv-heavy models with static inputs are easier to use for throughput stress testing and TOPS conversion.
Small object detection / OCR backbone ssdlite_mobilenet_v2, pp-ocr-det, pp-ocr-rec Practical workloads, but NMS, decode, and post-processing can reduce Effective TOPS.
Audio / speech small models aclnet-int8, DNS, or keyword-spotting models Small and regular inputs make them useful for NPU stability and low-power inference checks.
NLP encoder BERT-style INT8 or FP16-INT8 encoders MatMul-heavy workloads test another execution pattern, but TOPS conversion is usually less intuitive than ResNet-50.

13.2 Model Selection Checklist

  • Prefer INT8 or FP16-INT8 models.
  • Prefer fixed input shapes, for example 1x3x224x224.
  • Prefer OpenVINO IR format, meaning the model includes both .xml and .bin.
  • Use -d NPU for dedicated NPU testing. Avoid mixing fallback into the result with AUTO:NPU,CPU.
  • Keep resize, decode, NMS, tokenizer, and post-processing outside TOPS conversion whenever possible.

13.3 Not Recommended for Direct Peak TOPS Comparison

  • LLM token generation: bottlenecks are often memory, KV cache, and token loops, not pure INT8 dense compute.
  • Complete YOLO pipelines: NMS, decode, resize, and post-processing reduce Effective TOPS.
  • Dynamic-shape models: NPU execution is more likely to be limited or fail compilation.
  • FP16-only models: these may run on NPU, but they are not suitable for direct comparison with official INT8 TOPS.
